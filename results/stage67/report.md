# ステージ67 報告: 利益剰余金への移動コスト

**結論: 「利益剰余金が無料だから」という診断は誤りだった。**

利益剰余金に他の科目と同じ規則で移動コストを与えても、次の 3 つはいずれも変わらなかった(両 class、事前に決めた C.3 の判定)。

- ΔRE/ΔNA の中央値: 1.00 → 1.00(差 0.000 [0.000, 0.000])
- 変更された科目数: 5 → 6(class 2)、5 → 5(class 1)
- 払込資本を増やす企業: 差 +0.00

変わったのは総量だけだった。純資産の改善は class 2 で 0.270 → 0.215(差 −0.041 [−0.057, −0.020])に下がり、構成はそのまま。

結果を見てからの診断では、原因は対応先(目標)の側にある。

- 健全企業の対応先は、払込資本が始点より小さい(82〜83% の企業)。
- そのため、第 1 項は払込資本を**減らす**方向に引く。
- 増資は、対応先から離れる方向になる。
- 払込資本が増えるのは、利益剰余金が γ の上限に当たり、あふれた分だけだった(設定 1〜3 の払込資本の増加は全件、γ が拘束する企業)。

λ はすべて class 1(128 社)だけで較正し、class 2 には同じ λ を当てはめた。15 項目の違反は全設定・両 class で 0。

規則と決定は生成の前に `criteria.md` に記録した(コミット fcc50aa)。

## 3. B.3 γ との関係

| 設定 | γ が拘束(class 2 / 55) | γ が拘束(class 1 / 128) | 払込資本↑ のうち γ が拘束(c2 / c1) |
|---|---:|---:|---|
| 1 現行 | 10 | 13 | 3/3 · 2/2 |
| **2 + RE にコスト** | **9** | **10** | 3/3 · 2/2 |
| 3 2 + 階層分離 | 9 | 6 | 7/7 · 5/5 |
| 4 2 + Elastic-Net | 2 | 5 | 2/3 · 2/4 |
| 5 2 + 階層分離 + EN | 2 | 1 | 2/4 · 1/1 |

- c_RE > 0 で、γ が拘束する企業は**減ったが、少しだけ**(10 → 9、13 → 10)。
  - 設定 4・5 で大きく減るのは λ̃ が大きい(3、10)からで、コストの効果ではない。
- **γ は冗長ではない。**
  - 設定 1〜3 では、払込資本を増やした企業はすべて γ が拘束する企業だった。
  - 例: ANAP(`bs.md`)。利益剰余金が上限の −2,621 で止まり、短期借入金 2,550 → 101 の減少分を、資本剰余金 839 → 2,621 で埋めている。
  - γ を外すと、利益剰余金がこの分も吸収し、払込資本の増加はさらに減ると考えられる(γ を外した生成はしていない)。
- **判断: γ は残す。**

利益剰余金のコストで変わったもの:

### 他の要因(結果を見てからの診断。事前の判定ではない)

1. **ΔRE/ΔNA = 1 は恒等式。**
   - 純資産の部の科目は、利益剰余金・払込資本・自己株式・評価差額金・非支配株主持分など。
   - 利益剰余金以外の純資産の科目が動かなければ、ΔNA = ΔRE が厳密に成り立つ。
   - したがって、この指標は「利益剰余金以外の純資産の科目が動くか」を測っている。コストの大小は、利益剰余金の動く量を変えても、他の科目を動かす理由にはならない。
2. **対応先の払込資本は、始点より小さい**(`realdata.md` 末尾)。
   - 対応先(健全企業)の払込資本が始点より小さい企業は、class 2 で 82%(差の中央値 −0.604)、class 1 で 83%(−0.253)。
   - 対応先に完全に到達したときの ΔRE/ΔNA の中央値は 2.13 / 1.81 で、1 より**大きい**(利益剰余金を増やし、払込資本を減らす方向)。
   - 実データの再建(0.69 / 0.92)は 1 より**小さい**(増資する)。**目標の向きが、実データの再建と逆である。**
   - 第 1 項は払込資本を減らす方向に引き、増資は対応先から離れる。利益剰余金を高くしても、増資が「相対的に安く」なることはない。
3. **払込資本を減らす方向も、m = 10(ステージ62)で抑えている。**
   - 払込資本は、増える方向(目標から離れる)にも減る方向(m で抑えた)にも動かない。
   - 残る経路は利益剰余金だけで、比が 1 になる。
4. **増資が現れるのは、γ のあふれだけ。**
   - 利益剰余金が上限に当たったとき、貸借一致を保つために資本剰余金が増える(§3)。
   - 増資は、目的関数が選んだものではなく、制約の副産物である。

健全企業の構成(水準)に近づけることは、再建企業の経路(増資と利益の両方)とは違う。この食い違いは、移動コストでも距離の重みでも直せない。

直すには、目標の定義を変える必要があると考える(例: 再建企業の変化 Δ を目標にする)。ただし、本ステージでは検証していない。

## 8. 想定と違った点

1. **ΔRE/ΔNA は 1.00 のまま、少しも下がらなかった。** 「大きくは下がらない」とは予想していたが、比は恒等式で 1 に張り付いていて、コストでは原理的に動かなかった。
2. **対応先は払込資本を減らす向き**(到達したときの比が 2.13 / 1.81)。ステージ66 までの「払込資本が増えない」の原因は、移動コストより目標の側にあった。
3. **増資は γ のあふれでしか現れない。** γ は冗長どころか、増資を生む唯一の経路だった。
4. **利益剰余金のコストは総量を減らすだけで、λ と同じ働きをした。** class 1 の L は悪化した(3.35 → 3.82)。
5. **指示文の前提の違い:**
   - 丸め残余は c = 0 ではなく c ≈ 1,000(§1)。
   - class 1 用の c_RE は 15 社で、減少は n = 4。代替した。
6. **プロセス分離の違反が見つかった(ステージ61 から)。**
   - 原因: `density_stage51.load_tilde` を読み込むと sklearn も読み込まれ、cvxpy の QP(qp_stage61/66/67)や POT の輸送と同じプロセスに入っていた。
   - 修正: `scripts/tilde_stage51.py` に分離し、27 本のスクリプトの読み込み先を変えた。QP のプロセスには cvxpy だけが入ることを確認した。
   - POT 自体も import 時に torch と sklearn を読み込む。ステージ11-A の対策(`POT_BACKEND_DISABLE_PYTORCH` と `sys.modules["sklearn"] = None`)を、ot_stage60/64/66 に入れていなかった。
     - 入れた後は、輸送のプロセスに POT だけが入ることを確認した。
     - ot_stage64 の class 2 を再実行し、対応先(npz の全配列)が完全に一致することを確かめた。
   - 未対処: ステージ13〜38 の生成スクリプト(`run_generation_stage16/34/38.py` など)も、`fsgen.models.transport` が import 時に ot を読み込むので、POT・torch・sklearn・cvxpy が同じプロセスに入っている。HANDOFF の既知の限界に記録した。

   - すべて選ばなかった λ̃(0.003、0.01、30、100)。不可能は 0。
