# ステージ70 報告: コスト定義の純粋化と、輸送計画の複数企業を統合する目標

**結論: 採用なし。最終設定はステージ69 のまま。**

- **A.1**: 72 社に統合すると、n < 5 の代替が必要な方向は 12(15 社プール)→ **2** に減る。
- **A.2(最重要)**: M1(重み付き中央値)と M2(スパース重心)は、ゼロの構造を保つ。
  - 例: τ1 = 0.05 で、ちょうど 0 の科目が M1 8.60 / 7.81、M2 8.05 / 7.42(健全企業 6.70、L2 重心 1.05 / 0.03)。
  - しかし**識別 AUC は実在企業並みに下がらない**: M1 0.843 / 0.876、M2 0.940 / 0.952(実在企業の無作為抽出 0.47 / 0.48、ステージ69 の目標 0.712 / 0.686)。
  - 複数企業に広げるほど AUC は上がる。「1 社に絞らなくてもリアルな目標を作れる」ことは、**示せなかった**。
- **B**: 事前の判定(`criteria.md` §4)を満たす設定はない。
  - M1・M2 の全設定が条件 3(AUC)で落ちる。
  - 新設計の多くは、class 1 の 1 社(S100UG53)の項目 5 違反のため λ̃*_0 = 10 になり、ほとんど動かない(条件 4 も落ちる)。
  - 唯一、M1 + バランス OT(設定 4、m = 10)は、違反 0 で純資産の改善が class 2 で有意に高い(+0.123)。ただし、目標の AUC が 0.918 / 0.984 で、目標が実在企業とほぼ完全に区別できる。

規則・目標の定義・判定は、計算の前に記録した(`criteria.md`、コミット d765436)。

**確認したいこと 1**(複数企業に広げても、M1・M2 で 0 の数が健全企業並みに保たれ、AUC が劇的に下がるか):

- **0 の数は保たれる。** M1 は τ1 = 0.05 で 8.60 / 7.81、バランス OT でも 5.80 / 6.09。L2 重心の 0.00〜1.05 と比べて桁違いに多く、命題 2 の崩壊は避けられる。
- **AUC は下がらない。** M1 は 0.84〜0.98、M2 は 0.94〜0.99。L2 重心(0.97〜1.00)より少し低いだけで、実在企業(0.47)にも argmax(0.63〜0.74)にも遠い。
- 質量を広げるほど AUC は上がる。M1 が argmax 並み(0.735 / 0.655)なのは、実効サポートが 1.6 の τ1 = 0.01 だけ。
- 非支配株主持分を 0 にした版、class 1 を 57 社で推定した版も、ほぼ同じ(M1、τ1 = 0.05 で 0.838 / 0.869 と 0.853)。

**確認したいこと 2**(1 社に絞らなくても、輸送計画全体からリアルな目標を作れるか): **この方法では示せなかった。**

**原因の診断**(結果を見てから追加、判定には使わない。`diag_m1.md`):

- **M1 は BS の全体の整合を壊す。** 科目ごとに中央値を取るので、総資産の中央値は 0.96(τ1 = 0.05)〜0.91(バランス)、貸借一致の残差 |Cᵀτ| の中央値は 0.05〜0.09(実在企業は 10⁻⁸)。ロジスティック回帰でも 0.83〜0.98 で見分けられる。
- **ゼロの「数」は保てても、「組み合わせ」は実在企業と違う。** 0 かどうか(0/1)だけを特徴量にしても AUC 0.69〜0.82。科目ごとの多数決の組み合わせは、どの実在企業のゼロのパターンとも一致しない。
- **M2 は貸借の残差が小さい**(0.02〜0.03)が、非ゼロの値を条件付き平均にするので、値が「典型的すぎる」。LightGBM では 0.94〜0.97。
- 貸借一致へ L2 で補正すると、残差を全科目に配るためゼロが消え(8.60 → 0.78)、AUC は 0.99 に上がる。補正で救うことはできない。

### λ̃*_0 = 10 の原因と感度(結果を見てから追加、判定には使わない。`sensitivity.md`)

- 新設計では、class 1 の **S100UG53** が λ̃ ≤ 3 で項目 5(負債が 2 倍超)に違反する。
  - 始点の負債は総資産の 0.038。新しいコストで対応先が、未払金の大きい企業に変わった(未払金 0.019 → 0.126、負債 0.145)。
- この 1 社の違反だけで、M1(バランス)以外の全設定が λ̃ = 10(ほとんど動かない点)になった。
- この 1 社を較正の条件から外すと:
  - M1(τ1 = 0.05)・m = 10 は λ̃ = 0.3 になり、純資産の改善は class 2 で 0.435(設定 1 との差 +0.148 [+0.108, +0.185])、class 1 で 0.202(+0.036 [+0.000, +0.070])。
  - ただし class 1 の順位相関は有意に劣る(記号「+ 0 −」)。目標の AUC は変わらず条件 3 を満たさないので、判定は変わらない。
- 新設計のコスト・凍結(設定 2)単独の効果も、この 1 社に左右される。
  - 事前の規則では、純資産の改善が class 2 で −0.150、class 1 で −0.130(有意に劣る)。
  - 1 社を外すと λ̃ = 1 で +0.047 / +0.000(class 1 の順位相関は劣る)。
- **新設計が劣るのは、主に「1 社の項目 5 が λ を 10 倍にする」ことによる。** 設計そのものの優劣は、この結果からは言えない。

## 4. 新たなメイン手法に据えられるか(判定)

**据えられない。**

- **M1・M2 は、輸送計画の複数企業を統合しながらゼロの数を保つ**(命題 2 の崩壊は避けられる)。この点は確認できた。
- **しかし統合した目標は、実在企業と見分けられる**(AUC 0.84〜0.99)。
  - 原因は、科目ごとの統合が BS の全体の整合(貸借一致・総資産・ゼロの組み合わせ)を壊すこと。ゼロの数の問題ではない。
  - 実在企業らしさを測る限り、輸送計画の行を 1 社(argmax)に絞ることには、本研究の設定では依然として意味がある。
- **設定 4(M1 + バランス OT、m = 10)は、主指標では設定 1 より良い。** 純資産の改善 0.414 対 0.270(+0.123)、解消率 1.00 対 0.92。
  - ただし目標の AUC は 0.918 / 0.984 で、事前の条件 3 を大きく外れる。目標が「実在しない企業」である点は、L2 重心と同じ問題を残す。
  - class 1 の順位相関も低い(+0.261 対 +0.447、差 −0.186 [−0.288, +0.003])。

## 5. 想定と違った点

1. **ゼロの数を保っても AUC は下がらなかった。** 指示文の予想(M1・M2 なら実在企業並み)と逆。
   - 識別の手がかりは、ゼロの数ではなく、全体の整合とゼロの組み合わせだった。
   - 命題 2(ゼロの消失)は、重心が見分けられる理由の一部でしかない。
2. **実効サポートの τ1 依存が、指示文の想定より急だった。** 新しいコストでは、τ1 = 0.05 ですでに 13.6 / 10.2 社(class 2 は 1.0〜59 と広い)。
   - 「3〜15 社」に入るのは τ1 = 0.05 だけで、0.1 では 41.5 / 18.1 社。
3. **1 社の項目 5 違反が、ほぼ全設定の λ を決めた。**
   - 新しいコストで対応先が変わり、負債の極端に少ない始点の負債が 2 倍を超えた。
   - ステージ68 の T2 と同じく、項目 5 が実データ寄りの変化を排除する。
4. **新設計の多くで、class 1 の順位相関が有意に下がる**(λ̃ = 10 で動かないため。感度の表でも class 1 の順位相関は「−」が多い)。
5. **バランス OT の Sinkhorn で、POT の内部の exp がオーバーフローの警告を出した**(`ot/backend.py`)。
   - 計画は有限で、周辺の誤差は 8 × 10⁻¹¹ 以下、収束の検査も通った。結果は有効と判断した。
6. **M1 の目標は貸借が一致しない**(ANAP で −118 百万円、`bs.md`)。QP の終点は貸借一致を満たす。
   - 新設計(λ̃ = 10)では、ANAP の債務超過は解消しない(純資産 −317)。
