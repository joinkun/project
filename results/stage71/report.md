**結論(事前の判定): 採用なし。最終設定はステージ69 のまま。**

ただし、この判定は**私の実装の不備(数値の許容の食い違い)に強く左右された**。結論を読むときは、次の 2 点に注意してほしい。

1. **負債の上限(𝓕⁺)は効いたが、チェックとの許容が食い違った。**
   - 終点は上限ちょうど(L(y)/L(x0) = 2.0000000000013)に止まる。項目 5 のチェックは許容なしの「> 2」なので、10⁻¹³〜10⁻¹⁰ の数値誤差が違反と数えられた。
   - class 1 の 38 件はすべてこの境界の誤差で、QP の受け入れ許容(10⁻⁷)を超えるものは 0 件。
   - このため、λ̃*_0 は数値の雑音で決まった。違反がたまたま 0 になった λ̃ = 0.01 か、10(ほとんど動かない点)。

   - F2・F3 は、class 1 の順位相関で有意に劣る。

**F1 は、事前に決めた 4 条件のうち条件 4 だけを、私の制約の実装の不備のせいで落とした可能性が高い。** 採用するかどうかは、許容をそろえた形で改めて事前に記録したうえで判定すべきと考える(§5 の提案)。

## 5. 結論と提案

- **F1(事後アンサンブル)は、輸送計画の複数企業を、実在企業を壊さずに反映できる定式化**である。
  - 終点は 𝓕⁺ の凸結合で、全制約と貸借一致を満たす。
  - λ̃ = 0.3(許容をそろえた場合)では、両 class で設定 1 より純資産の改善が高く、主指標で劣るものがない(感度、`sensitivity.md` §2)。
  - BS 表(`bs.md`)でも、ANAP は短期借入金 2,550 → 31、資本剰余金を約 2,000 増やして債務超過を解消し(純資産 566)、自然に読める。
- **F2 は class 2 で最も強い**(+0.138)。しかし class 1 の順位相関が大きく劣る(−0.334)。
- **F3 は、ゼロを保つには 1 社に絞る必要があり、argmax に戻る。** 混ぜると目標の AUC が上がる。
- **事前の判定では採用なし。** 原因の一つは、私が 𝓕⁺ を項目 5 とちょうど同じ境界で実装したこと。QP の許容(10⁻⁷)とチェックの許容(0)が食い違い、λ の較正が数値誤差で決まった。

**提案**: 次のどちらかを事前に記録して、F1 の判定をやり直すのがよいと考える。

- (a) 負債の上限に小さな余裕を入れる(例: L(y) ≤ (1 − 10⁻⁶) × max(2 L(x0), 0.01 A(x0)))。
- (b) 項目 5 のチェックに、他の項目と同じ丸めの許容を入れる。

(a) は既存の結果を変えない。(b) は過去の全ステージの評価にも影響しうる(過去の生成では負債の上限がないので、境界の違反は起きていないはず)。

どちらを採るかは判断を仰ぎたい。

## 6. 想定と違った点

1. **境界の数値誤差が、較正全体を決めた**(上記)。ステージ70 で 1 社が決めたのと同じ構造で、今回は私の実装が原因。
2. **終点の「ちょうど 0」と AUC は、事前の定義では比較に使えなかった**(QP の解が厳密な 0 を返さない)。
3. **λ̃ = 0.01 は事実上「目標への射影」**で、払込資本↓ が 63〜68%、class 1 の順位相関が負になる。違反がたまたま 0 になる点が選ばれると、こうなる。
4. **F3 のハミング 0 は 1 社しか残らない**(上位 10 社の中で、ゼロのパターンが argmax と完全に一致する企業はほぼない)。ゼロのパターンは企業ごとにほぼ固有。
